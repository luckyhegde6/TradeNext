- **v3.9.1** — Swing `analysisStatus` Honesty Fix (Live-Verified Prod Bug) + Live Verification of v3.9.0 (August 14, 2026):
  - **Bug (found LIVE on tradenext6.netlify.app, v3.9.0 deployed)**: the Swing tab header badge rendered **"AI targets ready"** (emerald, `analysisStatus: "done"`) while EVERY card rendered "AI targets unavailable (Swing batch failed after 2 attempts: Unusable AI response (p) — screener signals only)". Root cause: `swingRecommendationService.ts` set `analysisStatus = "done"` UNCONDITIONALLY after `analyzeSwingStocks` returned — but the swing agent **never throws on per-stock failures** (it attaches `analysisError` per stock and swallows), so a fully-failed batch still reported "done" to the UI. The `catch` path (`"failed"`) only fired on a hard exception, which the agent-by-design doesn't raise.
  - **Fix**: NEW pure exported `analysisStatusAfterBatch(stocks)` in `lib/services/swingRecommendationService.ts` — returns `"done"` only when at least ONE stock carries `analysis`; otherwise `"failed"`. The `analyze=false` path keeps its initial `"skipped"` (unchanged). Header badge (`ANALYSIS_STATUS_META` in `SwingTab.tsx`) now matches the cards: a fully-failed AI batch shows the amber "AI targets failed" pill instead of lying "AI targets ready".
  - **Live verification (v3.9.0 on tradenext6.netlify.app)** — all PASSED:
    - Swing tab: "20 picks · 200 flagged · 34 screeners", family chips (All/Trend/Breakout/Reversal/Momentum/Volume/Range), 20 pick cards (SARDAEN, ASTRAL, EDELWEISS, AEQUS, NETWEB, BBOX, AZAD, SOLARINDS, INGERRAND, LMW, TI, CONCOR, NATCOPHARM, TMCV, GUJENERGY, FLUOROCHEM, RADICO, BLS, BDL, CARBORUNIV), "TV fallback" source badges, "+30 more ▼" screener expand, refresh, disclaimer footer.
    - Chart buttons: Today's Picks AXISBANK → `charting.nseindia.com/?symbol=AXISBANK-EQ`; `/markets` NIFTY BANK → `?symbol=NIFTY%20BANK` (no -EQ); outer card link never fired; 90 buttons incl. movers + index cards.
    - **0 console errors/warnings** desktop + mobile 375px; mobile Swing tab renders cleanly.
  - **Prod data gap (NOT a code bug)**: ALL swing indicators render "—" on prod because `daily_prices` has **0–1 rows per swing pick** — the v3.6.0 market-sync cron syncs the stock LIST + corp actions + screeners, NOT daily prices; `computeIndicatorsFromSeries` needs ≥2 bars (`momentum10/20` need 10/20).   - **Feature 1 — Swing tab on `/recommendations`** (user-requested "swing trading signals" section). NEW `GET /api/recommendations/swing` (`runtime="nodejs"`, `force=1` / `analyze=0`) runs the **34 swing-category Chartink templates** through the v3.5.6 unified runner (fresh DB rows → live Chartink scan → ONE shared TradingView `advancedScan` fallback):
    - **Registry**: NEW `lib/services/chartink-scans/swing.json` (34 entries) + `{ id: "swing", name: "Swing Trading Scan" }` appended to `CATEGORIES` in `lib/services/chartinkTemplates.ts`.
    - **Segregation**: `segregateAndDedupe` maps each flagged template name → **signal family** via keyword regex (`FAMILY_RULES`: momentum/breakout/trend/mean-reversion/crossover/bearish; default family "trend"), unions the per-family `screenerNames`, then dedupes by symbol.
