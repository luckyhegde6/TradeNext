# Version History v3.13

> From TradeNext version history. Index: [../CHANGELOG.md](../CHANGELOG.md). All v3.x files: [versions-v3.md](./versions-v3.md).

- **v3.13.0** — DB-backed Swing AI analysis job — durable `SwingAnalysisJob` replaces the volatile cache-only fire-and-forget (Option A, user-approved) (August 16, 2026):
  - **Why**: the v3.12.0 async split fixed Netlify's 30s wall but left the analysis state VOLATILE — the pending payload lived in the in-memory `staticCache` (LRU — the tab's 10s poll churn could evict it mid-analysis), the module guard allowed only ONE in-flight job per process, and a Netlify instance restart mid-run lost the job + progress forever. The Swing tab needed Refresh → pending → done to survive process restarts, cache eviction, and multiple concurrent readers/instances.
  - **Fix** (Option A, user-approved — new migration + tests pre-approved): NEW Prisma model `SwingAnalysisJob` (placed after `DailyRecommendationStock`; migration `20260816000000_add_swing_analysis_job`). **Local migration path**: the local `tradenext` DB has NO `_prisma_migrations` ledger (79 tables) — `migrate dev` would detect drift and attempt a destructive reset — so the migration was generated via `npx prisma migrate diff --from-config-datasource --to-schema prisma\schema.prisma --script` and applied via `npx prisma db execute --file` (Prisma 7: `--from-url` removed; `db execute` reads the datasource from `prisma.config.ts`), then `prisma generate`. Prod applies it normally via `migrate deploy` on build. ⚠️ Pre-existing: never run `migrate dev` locally until the ledger issue is fixed.
  - **Service rewrite** (`lib/services/swingRecommendationService.ts`): `getSwingRecommendations({analyze:true})` now does a **pre-scan DB lookup** (`findFirst orderBy createdAt desc`) — a done/failed/pending/running job is served WITHOUT re-scanning (pending also kicks `maybeProcessSwingAnalysis()`); if absent → scan + create durable job (`status: "pending"`, frozen screener JSON) + return the pending feed. `force=1` **supersedes** pending/running jobs first (`updateMany → status "failed"`, error "Superseded by a newer force refresh"), then re-scans and creates a NEW job. Empty feed → synchronous skipped (no job, no cache write). REMOVED: `SWING_PENDING_TTL`, `swingAnalysisInFlight`, `runSwingAnalysisInBackground` (grep-verified 0 refs).
  - **Processor** (`processSwingAnalysisJob` / `maybeProcessSwingAnalysis`): atomic claim = `updateMany({where:{id,status:"pending"},data:{status:"running",startedAt,attemptCount:{increment:1}}})` — `count === 0` means another instance/request claimed it (multi-instance safe). After the AI batches the job is RE-READ and the final write **aborts unless status is still `running`** — a force-supersede racing the completion must not overwrite the newer job or warm the cache with stale data. Stale recovery: a `running` job with `startedAt < now - 45min` (`SWING_JOB_STALE_MS`) is reset to `pending` if `attemptCount < 2` (retry once) else failed "timed out after 2 attempt(s)". Audits SWING_ANALYSIS_START / COMPLETE / FAILED + SWING_RUN_COMPLETE. `persistSwingTrackers` runs only when done (non-fatal). Cache warmed with the final 30-min payload. Module guard `swingProcessorInFlight` + `flushSwingAnalysis()` test hook.
  - **Cache semantics (D5)**: the `swing:recommendations:ai` cache key now holds ONLY final done/failed — pending/running is ALWAYS served from the DB row (`jobToResponse`), so cache eviction or a process restart can't strand a pending tab (it keeps showing the frozen pending feed until the job resolves).
  - **Daemon drain**: `cron-daemon.ts`'s existing 60s `RESYNC_INTERVAL_MS` tick now dynamic-imports the service and calls `maybeProcessSwingAnalysis()` fire-and-forget (`.catch` logged) — pending jobs created while no request is in flight still get processed, and stale running jobs get recovered. No circular import.
  - **Types**: `SwingResponse` unchanged (done | skipped | pending | failed); `jobToResponse` maps job JSON → response; `analysisStatusAfterBatch(stocks)` result cast `as "done" | "failed"` for the Prisma `JsonValue` assignment.
  - **Tests** (`lib/__tests__/swingRecommendationService.test.ts`): stateful in-memory `swing_analysis_job` store (`__swingJobs`) mirroring the service's real query shapes — `findFirst`/`findMany` (orderBy createdAt asc/desc), compare ops `in/lt/lte/gt/gte`, `applyData` with `{increment: 1}` — plus the existing recommendation-tracker + cache mocks. NEW orchestration suite: durable pending→failed on processor error (retry state), success→done with targets persisted, completed-job served WITHOUT re-scan, pending frozen feed WITHOUT re-scan, force supersede (old jobs failed "Superseded…", new job created), no double-run on concurrent kicks (claim count 0 skips), stale recovery retry-once + exhaust→failed, supersede-mid-analysis abort (no cache warm, no status overwrite), `jobToResponse` unit cases.
