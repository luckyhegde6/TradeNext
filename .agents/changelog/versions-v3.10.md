- **v3.10.0** — Historical-Price Sync into `daily_prices` (Swing Indicators "—" Fix) + `backtest_history` Prod-Gap **FIX** (August 14, 2026):
  - **Problem (flagged live in v3.9.1)**: prod `daily_prices` holds **0–1 rows per swing pick** — the v3.6.0 market-sync cron syncs the stock LIST + corp actions + screeners, NOT daily prices — so every Swing momentum/RSI/EMA indicator renders "—" (`computeIndicatorsFromSeries` needs ≥2 bars; momentum 10/20 need 10/20). Local DB mirrors this (213 rows = 19 NIFTY50 tickers × 1 bar).
  - **NEW `lib/services/historicalPriceSyncService.ts`** — `syncHistoricalPrices({symbols?, days?, from?, to?, maxSymbols?, series?, fetchDelayMs?, dryRun?, maxDurationMs?, db?})`:
    - **Scope**: explicit `symbols` list OR default = NIFTY 50 constituents (`getIndexStocks`) ∪ `RecommendationTracker` symbols from the last 30 days ∪ live `ChartinkScreenerResult` symbols (`expiresAt > now`) — deduped/uppercased, capped (default 300; empty explicit list = sync NOTHING, no default fallback). Every scope source degrades to [] on failure.
    - **Window**: `buildDateRange` — explicit `from`/`to` (DD-MM-YYYY, validated, throws on malformed/inverted) else N calendar days back from today (default 180).
    - **Fetch**: `fetchSecurityWiseHistoricalData(symbol, from, to, "EQ")` (NSE generateSecurityWiseHistoricalData, existing fetcher). 200ms inter-symbol delay (NSE rate-limit respect), `maxDurationMs` hard stop (market-sync passes 6 min).
    - **Write**: multi-row `prisma.$executeRawUnsafe` upsert `INSERT INTO daily_prices (ticker,"tradeDate",open,high,low,close,volume,vwap) VALUES ($1..$8n) ON CONFLICT (ticker,"tradeDate") DO UPDATE SET …` — chunked 200 bars/statement, PostgreSQL `$n` params, `BigInt` volume, `null` for falsy volume. Idempotent — re-runs never duplicate/delete.
    - **Tolerance**: per-symbol failures collected in `errors[]` and logged, never thrown; empty scope short-circuits with a warning result. `db` override makes the service Prisma-independent for tests.
  - **Wiring**:
    - `lib/services/worker/worker-service.ts`: `historical_price_sync` task case + exported `executeHistoricalPriceSync(payload)` — **dry-run by default** (`dryRun:false` to write); forwards `symbols/days/from/to/maxSymbols/maxDurationMs`.
    - `netlify/functions/run-cron-background.ts`: NEW `historical-price-sync` background action (payload passthrough incl. `dryRun`, no cron-ledger row — ad-hoc manual trigger) AND **step 4 inside `market-sync`** — `executeHistoricalPriceSync({ dryRun:false, maxDurationMs: 6*60_000 })`, non-fatal like the screener step → the daily 06:31 IST market-sync now backfills N-day bars so prod Swing indicators populate automatically.
    - NEW `scripts/backfill-daily-prices.ts`: CLI wrapper — `--apply` (default dry-run), `--symbols A,B`, `--days N`, `--from/--to DD-MM-YYYY`, `--max-symbols N`; prints scope/bars/errors summary.
  - **Tests**: NEW `lib/__tests__/historicalPriceSyncService.test.ts` — 15 tests: `formatNseDate`/`buildDateRange` (defaults, overrides, malformed/inverted throws), `dedupeSymbols`, `resolveSyncScope` (explicit, default merge, cap + graceful degradation), `buildUpsertSql` (8-param-per-row shape, ON CONFLICT, BigInt volume, uppercase symbol), `syncHistoricalPrices` (empty-scope short-circuit, dry-run counts-no-writes, apply multi-chunk >200 bars, per-symbol error tolerance, `maxDurationMs` stop — deterministic via 200ms sleep vs 50ms cap). **Suite 660 pass** (was 653); `npx tsc --noEmit` — 0 errors on touched files; total 71 = exact pre-existing baseline. Local dry-run verified (`--symbols TCS --days 5` → 4 EQ bars fetched, 0 written, 0 errors, 0.8s). **Local `--apply` executed (user-approved 2026-08-14)**: `npx tsx --env-file=.env scripts/backfill-daily-prices.ts --apply --days 180` → 300-symbol scope, 266 fetched, **17,198 bars written, 0 errors, 658s**; DB verification: **17,411 rows / 286 symbols** (was 213/19), top symbols 70 bars each (latest 2026-08-12); NSE historical endpoint caps ~70 rows per response (fine — indicators need ≤20).
