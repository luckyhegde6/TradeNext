- **v3.5.0** — Recommendation Performance Tracking & Archival (August 7, 2026):
  - **3-Status Lifecycle**: Replaced the 30-day `EXPIRY_DAYS` path with `tracking → target_achieved / stop_loss_hit → archived (360d)`. Trackers stay visible in the Performance list after a target/SL hit until the 360-day sweep archives them.
  - **RecommendationArchive Table**: New Prisma model — frozen snapshot (symbol, trackerId, runDate, OHLC, category, recommendation, confidence, reasoning, finalStatus, returnPercent, daysTracked, statusHistory JSON, archivedReason, archivedAt). Migration `20260807103000_add_recommendation_archive`. `DailyRecommendationStock.trackerId` made nullable + `onDelete: SetNull` so per-run History rows survive tracker hard-delete (History/top-stocks switched to LEFT JOIN).
  - **4 PM IST SYSTEM Cron**: `ensureRecommendationCrons()` (in new `lib/services/recommendationCronService.ts`) upserts two Mon–Fri jobs: Daily Recommendations `30 4 * * 1-5` (10 AM IST) + Recommendation Performance Check `30 10 * * 1-5` (4 PM IST). Both local cron parsers (worker-engine + admin cron route) gained weekday-range support via new shared `lib/cron-parser.ts` (`calculateNextRun`); dow-only `v<=6` cap bug fixed.
  - **triggeredBy: system**: `spawnCronTask()` accepts a `triggeredBy` override; recommendation crons + admin-triggered runs mark worker tasks `triggeredBy: "system"` so TaskEvents/UnifiedEvents/AuditLog carry `triggerSource: "system"`. Audit actions added: `RECOMMENDATION_PERFORMANCE_CHECK`, `RECOMMENDATION_ARCHIVED`, `RECOMMENDATION_PERFORMANCE_MOVED`.
  - **Performance Service**: New `lib/services/recommendationPerformanceService.ts` — `getPerformanceList()` (trackers `createdAt < today`, cached 15 min via `recommendationsCache`, BigInt-safe), `archiveRecommendations()` (age ≥ 360d → snapshot → hard-delete, per-tracker create→delete for idempotency, `runInChunks`), `getPerformanceColumns()` (dynamic column metadata), `invalidateRecommendationsCache()`.
  - **Reworked `checkRecommendationPerformance()`**: statuses tracking→target_achieved/stop_loss_hit, updates currentPrice + change%, `RecommendationStatusHistory.triggerSource="system"`, folds archive sweep at end, invalidates cache after writes.
  - **Category Extension**: `timeHorizon` values extended `short|medium|long` → `btst|short|swing|medium|long`. Backfill script `scripts/backfill-recommendation-categories.ts` (idempotent): status `active`→`tracking`, legacy `expired` (age ≥360d → archive else tracking), screener→category mapping (15-min screeners → btst, short-term → short, momentum/breakout → swing). Ran on local dev DB: 683 tracking (short=554, swing=129), archived=0.
  - **Public Performance API**: `GET /api/recommendations/performance` — Zod-validated `limit/offset/status/category/recommendation/sort/order` (sort enum widened to 10 keys incl. `entryPrice`, `currentPrice`, `targetPrice`, `stopLoss`, `daysTracked`, `lastCheckedAt` — fixed 400 on UI sorts), cached, returns `{ items, total, columns, cachedAt }`. `GET ?columns=1` for dynamic column metadata.
  - **Admin API**: `POST /api/admin/recommendations/archive` (manual archival sweep, admin-only); `POST /api/admin/recommendations` `run_now`/`check_performance` now spawn worker tasks (`triggeredBy:"system"`) and return `taskId` (visible in `/admin/workers`).
  - **Performance Tab UI**: New 5th tab `📈 Performance` on `/recommendations` (between History and Dividends). `PerformanceTab.tsx` — API-driven dynamic columns (show/hide persisted in `localStorage` `tradenext:rec-perf-columns`), sortable headers, status badges (Tracking/Target Met/SL Hit), category chips, filters (status/category/recommendation), server-side pagination, skeleton/empty/error states, responsive (table scrolls <768px), dark-mode aware.
  - **Tests**: `lib/__tests__/cronParser.test.ts` (weekday ranges, both parsers) + `lib/__tests__/recommendationPerformanceService.test.ts` (status transitions, no 30-day expiry, 360d archive boundary, snapshot completeness, SetNull history survival) — 24 new tests. - **v3.4.1** — Prod Reliability Fixes: Recommendations Transaction Timeout + Top-50 Cap + Telegram Live Prices + History Prices + DB Monitoring Logs (August 6, 2026):
  - **Transaction Timeout Fix**: Replaced interactive `$transaction` in `runDailyRecommendations()` and `checkRecommendationPerformance()` with a `runInChunks()` bounded-concurrency helper (sequential chunks, configurable batch size). Prevents the prod error: `Transaction API error: A rollback cannot be executed on an expired transaction (5000ms timeout, 5501ms passed)`.
  - **Top-50 Recommendation Cap**: Added `rankAndCapRecommendations()` in `dailyRecommendationService.ts` — composite score = `screenerCount*10 + marketCapScore*2 + momentumScore` (marketCap bands ≥₹100Cr/₹1,000Cr/₹10,000Cr; momentum from changePercent). Downstream pipeline (trackers, stock entries, AI input, run record, events, audit, return value) all use `rankedResults`. `MAX_RECOMMENDED_STOCKS = 50`, `MAX_AI_STOCKS = 50`.
  - **Telegram Live Prices Fix**: (1) `checkRecommendationPerformance()` now calls `invalidateRecommendationsCache()` after updating tracker prices/statuses — previously the 23h NodeCache returned stale data; (2) broadcast always sends (non-HOLD picks first, HOLD fallback, BUY/SELL/HOLD breakdown, 4000-char truncation); (3) both Telegram handlers prefer `tracker.currentPrice ?? s.price`, use tracker target/SL, and show lifecycle status.
  - **History Tab Predicted vs Current**: `/api/recommendations/top-stocks/route.ts` now JOINs `recommendation_trackers` and returns `entryPrice`/`currentPrice`/`trackerStatus`; `HistoryTab.tsx` shows Predicted vs Current with color-coded return % and status badges (active/target_achieved/stop_loss_hit/expired).
  - **AI Monitoring Persistence**: `trackAiCall()` now fire-and-forgets `persistAiCallToDb()` (ServerLog `source="ai"`); merged DB+memory reads (`getAiCallsMerged`/`getAiStatsMerged`); admin page shows source badge.

- **v3.3.0** — Phase 5: Daily Recommendations Engine + Self-Heal AI + Audit Logging (July 19, 2026):
  - **Chartink Integration**: Hybrid approach — tries Chartink's `POST /screener/process` API first, falls back to equivalent TradingView screener templates. For each stock: BUY/HOLD/SELL recommendation, confidence score (0-100%), target price, stop loss, time horizon (short/medium/long term), key reasoning, risk factors. Processes in batches of 5 to stay within token limits.
  - **Database Schema**: 8 new Prisma models — `RecommendationTracker` (long-lived stock tracking), `DailyRecommendationRun` (daily execution records), `DailyRecommendationStock` (per-run stock entries), `RecommendationStatusHistory` (status audit trail), `RecommendationAlertSubscription` (user subscriptions), `AgentPerformanceLog` (prediction accuracy), `ScreenerRunLog` (screener execution tracking), `SystemHealthLog` (health metrics).
  - **Recommendation Service**: `lib/services/dailyRecommendationService.ts` — Orchestrates screeners → dedup → AI analysis → DB storage → Telegram broadcast. Separate `checkPerformance()` function for status tracking.
  - **Cron Jobs**: Daily recommendations at 10 AM IST (04:30 UTC), performance tracking at 3:30 PM IST (10:00 UTC). Uses existing worker engine infrastructure.
  - **Public API**: `/api/recommendations` (latest), `/api/recommendations/history` (historical), `/api/recommendations/[symbol]` (detail). No auth required for viewing.
  - **Recommendations Page**: Tabbed layout — Today's Picks (AI-analyzed stocks with cards), History (past recommendations with performance), Dividends (moved from `/dividends`), Subscribe (Telegram subscription wizard).
  - **Performance Tracking**: Separate cron job monitors active recommendations against target/stop-loss prices. Updates `RecommendationTracker` status: active → target_achieved / stop_loss_hit / expired. Creates `RecommendationStatusHistory` entries.
  - **Self-Heal AI**: Circuit breaker for AI provider failures (3 failures → OPEN, 30s cooldown → HALF_OPEN), auto-retry with exponential backoff, model fallback chain (primary → secondary → tertiary → skip AI), performance degradation detection (success rate <80% warning, <60% critical).
  - **Self-Improve AI**: Prediction accuracy tracking (win/loss/breakeven), prompt versioning with auto-adjustment triggers, self-learning feed-back loop (daily accuracy calculation, weekly pattern identification, monthly prompt review).
  - **Comprehensive Audit Logging**: Unified event stream via `UnifiedEvent` model. Tracks Telegram events (subscribe/unsubscribe/verify/command/broadcast), AI agent usage (every trigger: button/cron/API), screener triggers (each run, success/failure, duration), system health metrics. Anomaly detection rules for accuracy drops, delivery failures, provider outages.
