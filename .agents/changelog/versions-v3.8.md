# Version History v3.8

> From TradeNext version history. Index: [../CHANGELOG.md](../CHANGELOG.md). All v3.x files: [versions-v3.md](./versions-v3.md).

- **v3.8.0** — AI Pre-Flight Gate + Cron Spawn Dedup + Stale-Task Reaping + Cron-Ledger Dedupe + 8192 maxTokens Default (August 13, 2026):
  - **Feature 1 — AI pre-flight gate** (`lib/services/dailyRecommendationService.ts`): the daily-run AI phase previously spent the whole 14-min background cap timing out batch after batch on a dead/unreachable model, then surfaced as "all-HOLD + AI failure" runs. NEW gate before the AI phase:
    - When `aiInput.length > 0` AND `hasValidConfig(aiConfig)`, run `runAiConnectionTest(preflightTimeoutMs = 120_000)` FIRST (a connection test through the v3.7.1 fallback chain: configured model → `openrouter/free` → `openrouter/auto`).
    - **status `ok`** → proceed with the configured model (`aiConfig.model`).
    - **status `fallback`** → run THIS run on `preflight.recommendedModel` (`logger.warn` shows configuredModel vs model so admins see the substitution).
    - **status `failed`** → `skipAi = true` → every stock mapped via the shared `holdFallback(reason, errorMsg)` helper (all-HOLD, confidence 50, price-based target/SL, `aiSuccess:false`, `tokensUsed: 0`) — fail fast instead of burning the background cap. Connection-test failures already audit + `notifyAdmins` (v3.7.1).
  - **Feature 2 — cron system-job dedupe** (`lib/services/recommendationCronService.ts`): `CronJob.name` has NO unique constraint, so two Netlify instances racing the findFirst-then-create pattern left duplicate rows for the same system job. `ensureRecommendationCrons` now runs a post-pass: system rows ordered by `createdAt: asc`, keep the EARLIEST per name, `deleteMany` the rest. Scoped strictly to the 4 system cron names — user crons untouched (test-verified).
  - **Feature 3 — worker stale-task reaping** (`lib/services/worker/worker-engine.ts`): NEW exported `reapStaleWorkerTasks(staleMs = STALE_MS = 16 * 60_000)` — a task stuck `running` past the cutoff is guaranteed dead (Netlify 15-min background cap / container recycle). Reaps `WorkerTask` `running` rows (`startedAt <= cutoff` → `failed` + error message) AND `DailyRecommendationRun` `running` rows (keyed on `createdAt` — that model has no `startedAt`). Throttled `maybeReap` ≤1/min from the poll loop + an initial pass at startup. `checkScheduledJobs` now EXPORTED (was private) so tests can drive the scheduler directly.
  - **Feature 4 — cron spawn dedup**: `DEDUP_WINDOW_MS = 90 * 60_000` — a due job that already has a pending/running `WorkerTask` for the same `cronJobId` created within the window skips re-spawning (prevents duplicate parallel runs from overlapping instances) but STILL advances `nextRun`.
  - **Feature 5 — AI config defaults** (`lib/services/ai/config.ts`): `maxTokens` default → **8192** (`DEFAULT_MODEL` unchanged: `nvidia/nemotron-3-ultra-550b-a55b:free`) — a 5-stock batch + JSON reasoning easily exceeds the old 2048 cap (truncated JSON → silent HOLD defaults; also truncated IPO-report-v2 JSON). **Caveat**: `loadConfig()` merges DB `ai_config` Secret metadata OVER env (DB wins) — a DB-stored `maxTokens: 2048` defeats the new default until the admin re-saves config via the UI.
  - **Feature 6 — connection-test plumbing**: NEW `getPromptTimeoutMs()` in `lib/services/ai/llm-provider.ts` — `DEFAULT_PROMPT_TIMEOUT_MS = 120_000`, env override `AI_PROMPT_TIMEOUT_MS`. Root cause: free-tier models routinely take 30–90s per batch; the old 30s cap aborted mid-generation and the batch layer mistook the abort for a successful-but-unparseable answer. `lib/services/ai/recommendation-agent.ts` now clamps each attempt's request timeout to the remaining batch budget (`Math.min(remaining, getPromptTimeoutMs())`).
  - **Tests**: NEW `lib/__tests__/worker-engine.test.ts` (7: reap WorkerTasks stuck running, reap DailyRecommendationRuns keyed on createdAt, no-op when nothing stale, never-throws-on-DB-failure returns zeros, skip-spawn when task pending/running in window, spawn + advance nextRun, no-op when no due jobs). `lib/__tests__/dailyRecommendationService.test.ts` +3 pre-flight (ok → configured model; fallback → recommendedModel; failed → all-HOLD `aiSuccess:false`) with a default `"ok"` pre-flight mock in `beforeEach` (the real module pulls in Prisma/network). `lib/__tests__/recommendationCronService.test.ts` +1 dedupe. `lib/__tests__/recommendation-agent.test.ts` mock + batch-isolation regex fix. **Suite 597 pass** (was 582); `npx tsc --noEmit` clean on touched files.
  - **Script**: NEW `scripts/cleanup-stale-worker-tasks.ts` — one-off ops tool; dry-run by default, `--apply` to write; reaps stale `WorkerTask`/`DailyRecommendationRun` rows + de-dupes `CronJob` rows by name (keep earliest).
