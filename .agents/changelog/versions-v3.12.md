# Version History v3.12

> From TradeNext version history. Index: [../CHANGELOG.md](../CHANGELOG.md). All v3.x files: [versions-v3.md](./versions-v3.md).

- **v3.12.0** — Swing tab prod failure FIX — request-time split: screener feed returns instantly (`analysisStatus: "pending"`), AI analysis runs in a fire-and-forget background task (August 16, 2026):
  - **Why**: on prod, `GET /api/recommendations/swing` ran the FULL pipeline synchronously — 34 Chartink templates (HTTP 419 → TradingView fallback, ~1-2s) THEN the AI analysis of the top 20 stocks (4 batches × 5, bounded concurrency, model retry/fallback) which takes **38–52s per batch**. Netlify's 30s request wall killed the request mid-batch-3 (`Analyzing swing batch, batchIndex=3, of=4` → `Duration: 30000 ms` in logs), so the Swing tab could NEVER load on prod.
  - **Fix** (in-process, persistent-server model — the same reality as the v3.11.x node-cron daemon): `getSwingRecommendations({analyze:true})` now returns the FAST screener feed immediately with `analysisStatus:"pending"` and kicks `runSwingAnalysisInBackground()` — a module-level guarded fire-and-forget task (`swingAnalysisInFlight` promise prevents double-running on concurrent tab/refresh/force requests; `flushSwingAnalysis()` test hook). The background runs the AI analysis, patches `s.analysis`/`s.analysisError`, computes the honest `analysisStatusAfterBatch` status, persists swing trackers (non-fatal), audits START/COMPLETE|FAILED + RUN_COMPLETE, and re-sets the SAME cache key with the final 30-min payload (`SWING_CACHE_TTL`). The pending payload is cached at a SHORT `SWING_PENDING_TTL` (10 min) so a stale pending self-expires if the process dies mid-run (tab would show failed state instead of hanging forever).
  - **Types**: `SwingResponse["analysisStatus"]` union extended with `"pending"` (done | skipped | pending | failed) + lifecycle doc comment.
  - **UI** (`SwingTab.tsx`): `ANALYSIS_STATUS_META` gains a `pending` entry — sky-blue pulsing "AI targets generating…" badge; SWR `refreshInterval` becomes function-form `(latestData) => latestData?.analysisStatus === "pending" ? 10_000 : 60_000` so the tab polls fast while generating and settles back to 60s (SWR ^2.3.7 supports function refreshInterval). Cards already render "AI analysis pending — screener signals only" when `analysis === null`.
  - **Prod-stability fix batch (same session, same branch)**: (1) **perf-check live-price fallback** — the prod perf run found 130 tracking trackers but only 8 had `daily_prices` rows → `checkRecommendationPerformance` now bridges missing symbols (cap 50) via `getStockQuote` in chunked 10-batch `Promise.allSettled` so Current/Return % no longer blank (4 new tests); (2) **prod `daily_prices` backfill APPLIED (user-approved)** — 3 passes (default 180d window / explicit `--symbols` for the 30-day-scope misses): 300+107+22 scoped → 246+85+7 fetched → **21,195 bars written, 0 errors** → tracking-tracker coverage **8 → 115/130 (88%)**, prod now **37,387 rows / 602 distinct tickers** (the remaining 15 return HTTP 200 with EMPTY data from NSE — anti-bot/data availability, NOT a code bug; covered at check time by the live-price fallback); (3) **worker reaper heartbeat-aware rewrite** — `reapStaleWorkerTasks` fails safe to `{0,0}` when the liveness lookup errors so a transient DB failure can't sweep RUNNING tasks to `failed` (worker-engine.test.ts 11/11); (4) **Prisma per-query timeout** — `lib/prisma.ts` gains `$extends({query:{$allOperations}})` + `Promise.race` (default 120s, `PRISMA_QUERY_TIMEOUT_MS` env) so a hung query can't wedge a run forever (prod probes had 30s+ slow queries during recs/perf runs); (5) **worker-logger `resolveLogsDir()`** — memoized `.next/server_logs` → `os.tmpdir()/tradenext-logs` → `""` fallback so Netlify's read-only FS can't crash file logging; (6) **error serialization** (`error instanceof Error ? error.message : String(error)`) in worker-engine + cron-daemon — pino drops non-enumerable Error props, prod logs showed `error={}`; (7) `scripts/fetch-swing-prices-to-prod.ts` dangling import fixed; (8) verified `DailyRecommendationStock` verdict writes are pipeline-only at runtime (read-only elsewhere — sync-local-to-prod manual writes unaffected).
  - **Verification**: suite **722 pass / 4 skip** (was 711/4 — +11: 4 perf-fallback, 4 reaper-sweep, 1 stage-log, 2 swing-orchestration additions carried from the split; 4 skips = intentional client-cache); tsc **46 = exact baseline, 0 new**. **Live-verified on :3000** (swing split): `force=1` request → **6s** with `analysisStatus=pending`, 20 stocks, analysis null; background log shows batches 1–4 with real AI calls (model `poolside/laguna-xs-2.1:free`, responseTimeMs 38–53s — all beyond the old 30s wall, proving the sync path could never have worked); subsequent request → **225ms** cached `done` with 20/20 AI targets (MARKSANS LONG 75%, LGEINDIA LONG 73%, MANORAMA LONG 70%); Swing tab renders "AI targets ready" + real targets, **0 console errors**.
