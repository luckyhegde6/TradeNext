## Findings

- **Fix 1 root cause**: `hasSuccessfulRunToday()` can never become true on an all-fail day, so v3.50.0's per-day *attempt* bound was the wrong layer — the correct bound is the *cause*: while the account-wide daily budget is spent, no attempt can succeed. Latching collapses ~70 futile runs/day into one short-circuit.
- **Fix 2 root cause**: `isPlanLimitHoldError` matched a *symptom class* (`timeout`) rather than the vendor's hold signal; `PrismaQueryTimeoutError` is our own deadline and is simultaneously `isDbUnavailableError`, so the aggressive predicate won by accident.
- **Fix 3 root cause**: two coupled errors — a status filter that only guards in-flight rows, and a constant window standing in for a per-job cadence, on a path where the schedule cursor is immutable by design.
- **v3.50.0 residual**: `dbHealthRoute.test.ts` was already red on `main` (async contract change without test update).
- **Doc budget**: only `scripts/dev-checks/check-doc-sizes.mjs` (32 KB/file, 100 KB total) gates docs; `document-normalize.test.ts` is unrelated.
