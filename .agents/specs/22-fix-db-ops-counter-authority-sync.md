# Spec 22: Fix DB ops counter authority sync (Sync Today/Month)\n\n## Problem statement\nThe DB Health Sync Operations Count UI lets the admin enter Reads/Writes from Prisma Console Total Operations dashboard and run Sync Today/Sync Month. After Sync Month, the displayed month total does not reflect the entered authority figure because buildQueryConsumption merges live dbOpsCounter values with persisted ledger using Math.max(persistedToday.reads, live.reads), so live counters can inflate the merged total above the authority-entered values.\n\n## Goal\nMake authority sync set today's ledger entry to exactly the entered reads/writes (not maxed with live). Live ops must continue counting after sync.\n\n## Non-goals\n- Change live ops counting\n- Change month aggregation beyond merge rule for today/authority context\n\n## Scope\n- lib/dbHealth.ts (buildQueryConsumption and merge logic)\n- app/api/admin/db-health/route.ts (syncToday/syncMonth)\n- lib/__tests__/dbHealthRoute.test.ts\n\n## Acceptance criteria\n1. syncToday persists exactly authority reads/writes for today's ledger entry.\n2. After syncMonth with authority values, month total equals the authority figure (today not inflated by Math.max with live).\n3. Live ops after sync still increment counters.\n4. No regression for other scopes (day/week/all).\n5. Existing dbHealth/dbHealthRoute tests still pass.\n\n## Design notes\n- Prefer authority values for today when applying authority sync (scope today/month with explicit reads/writes). Do not Math.max with live for that authority write.\n- Preserve 'honest' behavior for normal (non-authority) reads.\n\n## Risks\n- IST day boundary (use getIstDateKey)\n- Could mask growth if applied outside authority context\n\n## Verification\n- Unit tests for buildQueryConsumption\n- Route tests for syncToday/syncMonth\n- Manual verification on dev
