## 1. Overview

### Problem

Two related failure modes make long agent sessions unproductive:

1. **Compaction loop.** After a compaction, a handful of tool calls refill context and the
   system compacts again, repeatedly. Diagnosis: injected instruction files are already slim
   (**72.2 KB ≈ 18K tokens**), so the refill is the **conversation transcript** — large tool
   outputs and long summaries are re-sent on **every** request and remain resident after
   compaction. `compaction.reserved: 10000` leaves almost no headroom.
2. **No orchestration layer.** TradeNext has 13 specialist agents (all `"mode": "subagent"`)
   but **no orchestrator**: nothing decomposes a multi-part task, dispatches it in parallel,
   monitors subagent health, or hands off cleanly. Parallelism is therefore ad-hoc, and there
   is no way to detect a hung subagent.

A third, measured constraint shapes the design: **subagent execution currently fails** with
`OpenCode's free tier can only be used from within OpenCode`.

### Goals

- **G1** Eliminate avoidable context growth: large tool outputs never land in the transcript.
- **G2** Give agents a cheap durable memory so they stop re-reading large docs.
- **G3** Define an orchestration policy: decompose → parallelise when capable → monitor → hand off.
- **G4** Detect hung/stuck subagents instead of waiting on them.
- **G5** Improve agent-to-agent handoffs (structured, summarised, resumable).
- **G6** Tighten the code/test/build harness so regressions in the above are caught by gates.
- **G7** Document + test all of it, with decisions/flow maintained throughout.

### Non-Goals

- No application/feature behaviour change (no routes, DB, or UI).
- No new npm dependencies.
- No change to `main`; no deploy.
- Not rewriting the existing `.agents/` doc corpus again (v3.39.4 already slimmed it).
- Not optimising model/provider choice or cost.

## 4. Functions to Implement

### A. `scripts/dev-checks/check-context-budget.mjs` (extend existing guard)

Currently `check-doc-sizes.mjs` enforces the injected-file budget (100 KB total / 32 KB per file).

```
checkInjectedBudget(): { ok: boolean; total: number; files: {path,bytes}[] }
```

Extends the existing script (not a new one) to also warn when `.context/out/` grows past a
retention threshold and to expose a `--json` flag for CI consumption.

### B. `scripts/dev-checks/chunk-output.mjs` (new)

Turns a captured large output into grep-able chunks + an index.

```
chunkOutput(inputPath: string, opts: { lines: number; outDir: string }): Promise<ChunkIndex>
```

- Splits by line count (default 400), preserves original line numbers in each chunk header.
- Writes `<outDir>/<name>.index.md` listing chunk files + the first line of each.
- Idempotent: re-running over an unchanged input produces identical chunks.
- Pure Node built-ins only (matches `check-doc-sizes.mjs`; `import.meta.dirname` is available).

### C. `.remember/now.md` writer helper (documented convention, no code required)

No script: the convention is a one-line append. Documented in the rule (W2) rather than
implemented, to keep the change minimal.

## 10. Expected Behavior

### W1 — Tool-output protocol
An agent needing to inspect a large output runs the command with output redirected to
`.context/out/<name>.txt`, optionally chunks it, then uses `grep` or a bounded slice read.
Result: the transcript receives the answer, not the payload.

### W2 — Durable memory
An agent records a one-line event in `.remember/now.md` and promotes durable facts to the
memory MCP graph. A later session answers "where is X?" from the graph instead of reading the
source doc.

### W3 — Compaction headroom
`compaction.reserved` is large enough that a normal burst of tool calls does not immediately
re-trigger compaction.

### W4 — Orchestration
Given a task with ≥2 independent workstreams, the orchestrator decomposes it, dispatches
parallel subagents **if the provider allows it**, and otherwise executes a chunked-sequential
plan — stating which tier it used.

### W5 — Health monitoring
Every dispatched subagent has a timeout and a liveness check. On timeout/stall the orchestrator
aborts, records the failure, and either retries once or falls back to Tier B — never waits
indefinitely.

### W6 — Handoff
A handoff contains: context, progress, decisions, blockers, learnings, next steps (existing
schema) **plus** subagent status and a bounded summary. A fresh agent can resume from files
alone.

### W7 — Harness
CI/pre-commit fail on: injected-doc budget breach, tsc-error-count regression, and (recorded)
Turbopack warning count.

## 11. Error Handling

| Failure | Handling |
|---------|----------|
| Subagent dispatch fails (provider tier) | Log once, downgrade to Tier B, continue — never abort the epic (D11) |
| Subagent hangs past timeout | Abort, record in handoff `subagent-status`, retry once, else Tier B |
| `chunk-output.mjs` input missing/empty | Non-zero exit + clear message; no partial index |
| `.context/out/` exceeds retention | Warn only (scratch dir); never fail the build |
| Baseline file absent in `check-tsc-baseline.mjs` | Record current count, pass with a notice |
| `compaction.reserved` edit rejected | Report and continue; W3 is non-blocking |
| Doc-size budget exceeded | Fail with a per-file breakdown naming the offender |

All errors are surfaced with context; no silent failures.

## 12. Test Strategy

### Unit Tests (`lib/__tests__/`)
- `chunk-output.test.ts` — splits by line count; preserves original line numbers; idempotent
  re-run; empty input; input smaller than one chunk.
- `check-context-budget.test.ts` — parses `instructions` from `opencode.json`; computes
  total/per-file; fails when over budget; `--json` shape.
- `check-tsc-baseline.test.ts` — counts tsc errors from a fixture; regression detection;
  `--update` rewrites the baseline.

> Rationale for testing Node scripts under `lib/__tests__/`: Jest 30 config
> (`jest.config.cjs`) is the established runner and the scripts must not require a second
> harness.

### Integration Tests
- Run each script end-to-end against a temp fixture dir; assert exit codes + artifacts.
- Assert `.context/` and `.remember/` remain gitignored (`git check-ignore`).

### E2E Tests (`e2e/`)
**Not required** — no UI change. The 12 existing specs / 89 tests must continue to pass
unchanged (regression guard).

**Harness self-check**: the epic is complete only when `npm run test`, `npx tsc --noEmit`,
`npm run quickbuild`, and `npm run lint` are all green, and the new gates pass on the branch.
