3 · Phase 1 — Client wiring (lib/prisma.ts)

Extension order is documented and deliberate: otelSetup() FIRST (module top — PrismaInstrumentation wraps the query engine at client construction), then withAccelerate() as the base extension, then the $allOperations circuit-breaker/op-count/timeout extension wraps the cached reads. type AccelerateClient = PrismaClient is kept as the top type because base model read-args hard-code cacheStrategy: never and intersections don’t override it.

flowchart LR
    O["otelSetup()
(PRISMA_OTEL_ENABLED=1 opt-in)"] --> C["new PrismaClient({ accelerateUrl })
.$extends(withAccelerate())"]
    C --> A["$extends({ query: { $allOperations } })
circuit breaker · op counter · 120s timeout"]
    A --> H["withAccelerateCache(strategy)(args)
boundary helper — injects cacheStrategy
while preserving Prisma contextual typing"]
  • NEW withAccelerateCache(strategy) — pure transform via Parameters<T>[0] so literals like orderBy: 'asc'|'desc' still resolve; runtime client supports cacheStrategy, the base type doesn’t.
  • ACCELERATE_CACHE_TTL — Number(process.env.PRISMA_ACCELERATE_CACHE_TTL) || 300 (5-min default), exported for query sites.
