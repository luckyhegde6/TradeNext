TradeNext — Cache → SQLite → Prisma Stock-Quote Tiering

Live Prisma monitoring showed 2.0 QPS even in a closed after-market window and 14,166 Total Operations / day. User directives: “do not do a db write for every NSE fetch during after market hours … only write to cache” and “make the 1st hit be cache, then sqlite and then eventually the prisma db”. Fix: gate the market-hours-only write to once-per-symbol-per-trading-day, tier closed-market reads cache → SQLite → Prisma, fix a TTL ms-vs-seconds bug, and gate the price accumulator.

2 · Fix A — one write per symbol per trading day (market-open only)

The IIFE moves into a guarded helper syncDailyPriceOnce(quote): zero DB writes when the market is closed, and a seed-once globalThis Set keyed ${getIstDayKey()}:${symbol} limits market-open writes to one per symbol per IST day (the day-rollover auto-empties the Set; upsert failure removes the key so it retries).

3 · Fix B — closed-market read chain: cache → SQLite → Prisma

Tier 1 stays hotCache; NEW tier 2 = SQLite daily_price_snapshot table (symbol, tradeDate, open, high, low, close, volume, updatedAt — Prisma-agnostic, seeded by syncFromPrisma from the latest daily_prices rows on the same IST day); tier 3 = Prisma ONLY when SQLite is not ready or has no row.
