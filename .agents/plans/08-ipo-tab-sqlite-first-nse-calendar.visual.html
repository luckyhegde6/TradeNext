TradeNext — IPO Tab: SQLite-first NSE IPO Calendar

The IPO tab's feed becomes a resilient SQLite-first calendar built from three NSE endpoints (special pre-open / forthcoming listings / recent listings). Read chain: memory 15 min → SQLite mirror 6 h → NSE live (Promise.allSettled, partial success). The calendar service is zero-Prisma; Prisma gains it as a single change-gated market_cache row via the promote engine.

v3.30.0 branch fix/v3.28.1-sqlite-self-heal zero Prisma imports (calendar module) memory 15m · SQLite 6h ≤1 promote op (change-gated) SQLite-only — no Prisma migration

1 · The Problem

The IPO tab depended on a single legacy calendar source in market_cache plus per-symbol detail lookups; NSE rate-limiting / anti-bot behaviour made every refresh fragile, and the tab had no durable local mirror to serve during blips. The redesign mirrors the v3.28.0 SQLite-first pattern at IPO scale (3 endpoints, small data).

ConstraintDesign answer
NSE 3-endpoint rate limits / anti-botMemory 15-min front + SQLite 6-h mirror; Promise.allSettled partial success; existing nseFetch cookie flow
Calendar rows lack issuePrice/size/lotRendered via the existing per-symbol /detail chain for Active/Forthcoming (unchanged); per-symbol /detail SQLite tiering deferred
Legacy callers/tests of getUpcomingIpoIssuesCompat wrapper maps the calendar source back to legacy api|cache|db values
AI IPO analysis unavailable this periodOpenRouter quota — untouched (deferred)

2 · SQLite Mirror Table

NEW nse_ipo_listing in SCHEMA_SQL — SQLite-only, no Prisma migration. setIpoListings(category, rows) replaces per-category (transaction: DELETE … WHERE category = ? then INSERT batch — replaceChartinkResults style); getIpoListings(category) returns ordered by symbol. restoreSqliteBackup() validation gains the new table.

3 · nseIpoCalendarService — 3 Pure Normalizers

NEW server-only lib/services/nseIpoCalendarService.ts with types IpoCalendarCategory / IpoCalendarSource / NseIpoListing. All three normalizers never throw and coerce stringly numbers.

NormalizerCategoryStatusKey fields

Zero-Prisma guarantee: the module holds no @/lib/prisma import anywhere on the read path — verified by the "never-Prisma" test.

4 · Read Chain: memory → SQLite → NSE live

getNseIpoCalendar(forceRefresh = false) serves memory (ipo:calendar, IPO_CALENDAR_MEM_TTL_SECONDS = 15 * 60) → SQLite mirror (all three categories present AND fresh within IPO_MIRROR_FRESH_MS = 6h → merge, source:"sqlite_mirror"; stale-but-present still served for durability) → NSE live (Promise.allSettled over the 3 nseFetch calls), parse, per-category setIpoListings, memory set, source:"nse_live".

  • Compat — mapCalendarToIpoIssues(list) derives status; issueStartDate = effectiveDate ?? listingDate; issueEndDate = listingDate or effectiveDate for upcoming; issuePrice/issueSize/lotSize/priceBand stay null unless detail-filled (/detail chain unchanged).
