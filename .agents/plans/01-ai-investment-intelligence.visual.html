TradeNext — AI Investment Intelligence

Company-level AI research: cache-first orchestrator pulls 8 NSE data adapters in parallel, feeds a structured JSON prompt to the OpenRouter fallback chain, and renders an 11-section institutional-style panel — with honest data-gap surfacing (never fabricated).

v3.18.0 · branch feature/ai-intelligence cache-first + write-through dual-layer 8 NSE adapters (parallel) directPrompt + modelFallbackChain structured JSON verdict contract MCP getInvestmentIntelligence (29 fns) quota-exhausted guard

1 · The Problem

Symbol pages only showed quotes/technicals — no research depth. Ad-hoc solutions were either too slow (sync NSE calls per field) or fabricated answers (unstructured AI text with no evidence trail).

Pain pointDesign answer
Research takes many slow NSE round-trips✓ 8 independent adapters fetched via Promise.allSettled in parallel; each adapter try/catch → null on failure (graceful data gaps).
AI output unreliable / unbounded✓ Structured JSON prompt contract + markdown-fence-tolerant parser; numbers validated; missing fields → null + surfaced in dataGaps.
Re-running analysis is expensive✓ Write-through dual-layer cache (memory NodeCache ~1 ms + Prisma IntelligenceCache persistent, 7-day TTL) below the orchestrator.
Free-tier quota exhaustion⚠ isQuotaExhausted() guard aborts generation early and serves the cache / stale result.

2 · Orchestrator Architecture

Cache-first read → parallel adapters → AI prompt → fallback chain → parse → cache → audit. The UI (CompanyIntelligence) drives a 5-state button and an expandable 11-section panel.

Cache semantics: GET serves memory → DB, restoring DB rows back into memory on hit (write-through both directions). Generation is POST + auth + Zod-validated; every run is audit-logged (INTELLIGENCE_GENERATED / CACHE_HIT / FAILED / REQUESTED / UNAUTHORIZED).
