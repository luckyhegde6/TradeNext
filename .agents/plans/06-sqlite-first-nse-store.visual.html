TradeNext — SQLite-First NSE Data Store

SQLite becomes the primary store for NSE-backed market data — stock list, corporate actions, daily OHLCV/backtest bars and Chartink captures — with a hot memory cache on top. Read path: cache → SQLite → live NSE/Chartink fetch (Prisma is NOT a read fallback for NSE data). Every NSE sync writes SQLite-first, and a SQLite→Prisma instant promote (a ~1 min background timer + an end-of-task flush) keeps Prisma durable/shared for cross-instance consumers.

v3.28.0 branch v3.26.0-prod-failure-triage reads: cache → SQLite → live syncs write SQLite-first promote → Prisma no Prisma migration

1 · The Problem

NSE-backed reads and every NSE sync task used Prisma directly — every quote-adjacent read, corp-action refresh, OHLCV/backtest fetch and Chartink capture racked up Accelerate ops on a plan-limit watch. User directives (2026-09-04): syncs trigger against SQLite; all things cached; reads hit SQLite FIRST and only then live-fetch; add a Prisma-mirrored SQLite schema with indexes; and promote SQLite→Prisma instantly for the required tables.

Confirmed architecture (user-approved Q&A): SQLite-first write-through; Prisma stays the shared truth and the home for perf-runs / recommendation updates / auth / cross-instance coordination. Scope = all NSE syncs. Promote cadence = both (~1 min timer + end-of-task flush).

2 · Prisma-Mirrored SQLite Schema

Additive SQLite-only DDL added to SCHEMA_SQL (idempotent CREATE TABLE IF NOT EXISTS); column adds via an ensureNseColumns(db) PRAGMA-guarded ALTER. No Prisma schema change → no migration. Column sets map Prisma camelCase → SQLite snake_case (existing convention).

3 · Write-Through: Syncs Land in SQLite First

Every NSE sync task now writes SQLite-first, then flushes to Prisma (instant promote). Module-level exported helpers (setSymbols, setDailyPriceBars, setCorporateActions, setChartinkResults, setBacktestBars, getBacktestBars) delegate to the singleton fallback.

4 · Read Chain: cache → SQLite → live

Hot NSE reads attempt memory cache, then SQLite, then live NSE/Chartink fetch; on live success the data is written through to SQLite + cache. Prisma is never consulted in these read paths (it stays for perf runs, recommendation updates, auth, cross-instance coordination).

5 · Instant Promote: SQLite → Prisma

promoteNseToPrisma() reads each table's fresh SQLite rows in chunks and batched-upserts into Prisma (createMany + skipDuplicates, $transaction-chunked update for existing keys). Leader-gated + plan-breaker-gated (mirrors startWriteBehindFlush/syncFromPrisma guards).
