TradeNext — Daily Recommendation Pipeline Redesign: Top-100 + Top-Pick Confidence

The daily recommendation pipeline is rebuilt around a top-100 market-cap screener slice (MAX_AI_STOCKS 50→100) whose AI-analyzed results are partitioned into actionable vs HOLD; the top 50 BUY/SELL by confidence get isTopPick: true. The AI fallback chain is hardened so a primary-model failure tries fallbacks instead of skipping, and the Today's Picks UI shows BUY/SELL in the main grid with HOLDs collapsed separately.

v3.15.0 branch feat/recs-pipeline-v2 MAX_AI_STOCKS 50 → 100 top 50 → isTopPick AI fallback chain (not skip) HOLDs separate section

1 · Why Redesign the Pipeline

With 98 TradingView templates + the 117-entry Chartink registry feeding the run, the pre-v3.15.0 pipeline could surface hundreds of candidate stocks — the UI was unusable and the AI budget unbounded.

ProblemConsequence
643 recommendations surfaced✕ Too many to be useful — no cap, no prioritisation; users saw an endless mixed grid.
HOLDs mixed with BUY/SELL✕ Actionable picks were visually buried inside wall-of-cards of neutral HOLD verdicts (conf-50 noise).
AI model failure = skip✕ When the configured primary model failed, the batch layer could skip analysis entirely → synthetic all-HOLD fallback rows.

2 · Pipeline Redesign — Top-100 by Market Cap → Top-50 Confidence

In lib/services/dailyRecommendationService.ts: NEW pure selectTopByMarketCap(results, limit) sorts the full screener result set by marketCap descending and keeps the top N; rankAndCapRecommendations is replaced by selectTopByMarketCap(screenerResults, 100); after AI analysis the successes partition into actionable (recommendation !== "HOLD") vs holdOnly; actionable is ranked by confidence descending and the top 50 carry isTopPick: true. ALL results (incl. HOLDs) are stored for history/performance tracking — only the presentation is filtered.

  • Selection honesty — market-cap cut is applied to the screener universe BEFORE AI spend; the confidence cut is applied to the AI verdicts after analysis.
  • No data loss — the stored run keeps every analyzed stock, so History/Performance/Telegram see the full picture, not just the top 50.

3 · AI Fallback Chain Fix — Try Fallbacks, Don't Skip

In lib/services/ai/config.ts the shared modelChain carries the fallback model list; lib/services/ai/recommendation-agent.ts iterates modelFallbackChain so a primary-model failure attempts each fallback in order instead of skipping analysis for the batch. Per-batch logging records which model actually served.

  • Honest persistence — only real AI verdicts (success: true) are persisted; a fully-failed chain must NOT fall back to synthetic all-HOLD rows (v3.11.1 "no-fake-HOLD" discipline preserved).
  • Visibility — trackAiCall records usedModel so AI monitoring shows fallback usage, not just the configured model.

4 · DailyPicksTab — Top Picks Grid + Collapsible HOLDs

In app/components/recommendations/DailyPicksTab.tsx: the stock data type gains isTopPick; the main grid filters to isTopPick === true only; a collapsible "HOLDs (N)" section renders below the grid; the summary cards show "X Buy/Sell · Y Hold" instead of the raw total.
