Jev 1.13.0 — TypeSafe System One Model

Visual guide: the hosted System One decision model, the @typesafe-ai/sdk, and how TradeNext integrates it behind a provider-agnostic decision engine.

1. Identity — what Jev actually is

Premise correction: github.com/answers-ai/jev is a 404 — Jev is NOT open-source. It is TypeSafe AI's proprietary hosted API, the "first public System One model".

Core principle: Jev makes judgments, not prose. It never generates text and never picks its own next step — all decision logic lives in your code.

  1. One state per request, shared by all questions. No multi-turn memory — workflows re-issue requests in code.
  2. Atomic questions — each targets a single decision; ask more by adding questions, not complexity (speculative fan-out).
  3. Atomicy paths — a backticked path (e.g. `support.tickets[0].message`) points a question at a nested state slice; questions evaluate isolated values, so no "context-rot".
  4. Confidence-gated routing — thresholds per action, scaled by risk.

Confidence = f(probability shape): peaked → confident, flat → uncertain. Docs illustrate the (count·peak−1)/(count−1) family (flat→0, one-hot→1). Calibration: conf 0.2 → right ~20% of the time; 1.0 → ~100%.

4. Patterns — the four building blocks

flowchart TD P1["1 · Speculative fan-out
many atomic questions, ONE parallel request
≈ no extra latency"] P2["2 · Confidence-gated routing
high→act · med→review · low→escalate
risk-scaled thresholds"] P3["3 · Composite scoring
fuse Score answers: Σ wᵢ·scoreᵢ"] P4["4 · Intent routing
Choice classifies → switch code path"] P1 --> C["Combine in code"] P2 --> C P3 --> C P4 --> C C --> A["One auditable decision"]
  • Fan-out — unlike chat LLMs, adding questions to a System One request barely increases latency. Ask everything up front.
  • Confidence routing — read-only rank: act ≥ 0.55; emitting alerts: act ≥ 0.8; destructive: always human.
  • Composite scoring — multiple score answers → weighted sum → single rank/decision.
  • Intent routing — a choice over intents → branch in code.

5. SDK quickstart — from scratch

// 1. npm install @typesafe-ai/sdk      (v0.6.0 — Score.criteria = ordered tuple)
// 2. export TYPESAFE_API_KEY=sk-...      (TYPESAFE_BASE_URL / TYPESAFE_DEFAULT_MODEL optional)

import { TypeSafeClient, choice, score, noul } from "@typesafe-ai/sdk";

const client = new TypeSafeClient(); // reads TYPESAFE_* env

const res = await client.systemOne({
  state: { symbol: "RELIANCE", price: 2950.4, prevClose: 2870.1, changePct: 2.8 },
  questions: [
    choice({ name: "bias", options: ["bullish", "neutral", "bearish"] }),
    score({ name: "setup_quality", criteria: ["poor", "average", "good", "excellent"] }),
    noul({ name: "above_ma20", instruction: "Is the price above MA20?" }),
  ],
});

const bias      = res.answers["bias"];          // { choice, probabilities[], confidence }
const quality   = res.answers["setup_quality"]; // { score, probabilities[], confidence }
const gate      = res.answers["above_ma20"];    // { noul }

// discover models: await client.models.list();
