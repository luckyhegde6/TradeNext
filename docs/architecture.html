1. System Overview

TradeNext is a Next.js 16 + TypeScript + Prisma 7 + PostgreSQL (TimescaleDB) app serving NSE (India) market data. All NSE traffic flows through a server-side proxy only — the browser never calls NSE directly. Three cache tiers sit in front of the database and the NSE API:

  • Layer 1 In-memory NodeCache (lib/market-cache.ts — mc: keys, 300s/3600s TTL) and historicalCache (24h) for backtest bars.
  • Layer 2 MarketCache DB (market_cache table) — persistent store.
  • Layer 3 Main tables — daily_prices (read-only for backtests), backtest_history (temp, age-pruned).
  • Source NSE API (lib/nse-client.ts — cookies, retry, backoff).

Key Policy

Backtest data chain: NSE-fetched OHLCV bars are NEVER written to the main daily_prices table. They go to the age-pruned temp table backtest_history only. This keeps ad-hoc backtest fetches from bloating the canonical price store.

2. Backtest Data Chain

getBacktestData(symbol, from?, to?) in lib/services/backtestDataService.ts resolves bars through a 4-step chain. It returns dataSource so callers (and tests) know where the data came from:

StepSourcedataSourceNotes
1historicalCache (memory, 24h TTL)"memory"Fastest; 0 DB ops on hit.
2backtest_history temp table (fresh ≤ 24h)"db"Upserted when fetched; repopulates memory on read.
3daily_prices (main, read-only)"daily_prices"Only for symbols with enough synced history; never written.
4NSE historicalOR live fetch"nse"Upsert to temp table only; falls back to stale temp if NSE fails.
import { getBacktestData } from "@/lib/services/backtestDataService";
const { bars, ohlcv, barCount, source, rangeStart, rangeEnd, fetchedAt } =
  await getBacktestData("RELIANCE");
// source: "memory" | "db" | "daily_prices" | "nse"

5.3 Worker / cron integration

  • Recs engine 10:00 AM IST generation, 3:30 PM IST performance tracking (UTC 04:30 / 10:00).
  • Tasks & workers lib/services/worker/worker-service.ts — queue, priority, retries, runInChunks() bounded-concurrency for large batches (txn 5s limit).
  • Prune job (temp table) should run alongside existing worker maintenance (see .agents/docs/tasks-cron-workers.md).

7. MCP Integration

The MCP API (POST /api/mcp or GET /api/mcp?function=...) exposes 28 functions for external NSE data. getHistoricalData (added Aug 6, 2026) reuses getBacktestData() so MCP and the backtester share one data path. getIpoAnalysis / getIpoIssueDetail / getNseEvents (added Aug 12, 2026) expose the IPO report v2, IPO issue size, and the NSE events feed. getOptionChain / getFoExpiries (added Aug 13, 2026) expose the F&O option-chain-v3 data and expiry calendar.

9. Agentic Operating Model

Agents working in this repo follow a file-first memory model (no conversation-memory reliance):

flowchart LR A[Session Start
HANDOFF → latest.md
→ Primer → Lessons → todos] --> B[Plan
verifiable goals] B --> C[Implement
one todo at a time] C --> D[Verify
npm run test (alone) · tsc · lint] D --> E[Document
AGENTS.md version · TODO.md · Lessons] E --> F[Handoff
files not prose] F --> A
  • Read order: HANDOFF.md → .agents/handoffs/active/latest.md → Primer.md → Lessons.md → .agents/session-todos.md.
  • Handoff flows: session-cycle.md, agent-to-agent.md (HTTP-like status codes), agent-to-human.md (consent/decisions, status: awaiting_human), error-recovery.md.
  • Git (STRICT): never commit to main without explicit permission; feature branch + PR always (feat/, fix/, docs/, ph<N>).
  • Sensitive ops require explicit consent: DB migrations/schema changes, env files, package installs, auth/admin changes, production deploys, process kills.
  • Docs are mandatory: if documentation is not updated, the task is not complete.

10. Future Improvements

  • Idea Redis tier for historicalCache so bars survive process restarts (currently memory-only).
  • Idea Pre-seed temp table for the top-N symbols on a schedule, so backtests rarely hit NSE live.
  • Idea Bar-count-aware pruning — prune by rows AND symbol-age to bound table size.
  • Idea Multi-symbol batch fetch for MCP/backtest bulk workflows (respect NSE rate limits).
  • Idea Wire live-price SSE into Portfolio/Watchlist tables (hooks exist: useLivePrice/useLivePrices).
  • Idea Backtest provenance column (dataSource) persisted per run for auditability.
  • Idea Observability — emit cache hit/miss ratios + NSE fetch counts to ServerLog/unified events.
